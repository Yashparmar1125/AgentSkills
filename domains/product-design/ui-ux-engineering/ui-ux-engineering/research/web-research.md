# Web Research & Evidence Formulation Guide

## Purpose
This guide defines how to conduct systematic web research for UI/UX patterns, avoiding superficial search queries in favor of evidence-backed domain intelligence.

---

## 1. Domain Query Formulation Matrix

Transform generic prompts into targeted industry research queries:

| Product Domain | Poor Generic Query | Evidence-Driven Research Queries |
| :--- | :--- | :--- |
| **Exam & Assessment** | "quiz ui design" | `"online examination timer UX accessibility"`, `"candidate proctoring interface design patterns"`, `"assessment question navigation heuristics"` |
| **Analytics Dashboard** | "dashboard ui" | `"SaaS executive KPI ribbon visual hierarchy"`, `"student risk score visualization patterns"`, `"cohort retention matrix UI design"` |
| **Data Tables** | "table design" | `"enterprise data table batch action UX"`, `"responsive table mobile card transformation"`, `"data table column density and sorting heuristics"` |
| **Forms & Onboarding** | "form design" | `"multi-step checkout form cognitive load"`, `"inline field validation timing error UX"`, `"accessible password visibility toggle aria"` |

---

## 2. Evidence Synthesis Protocol

When evaluating web research results:
1. **Identify Proven Patterns**: Extract conventions established by leading design systems (e.g., Apple HIG, Google Material Design 3, Tailwind UI, Radix UI, Atlassian Design System, Carbon Design System).
2. **Identify Cognitive Friction**: Look for user complaints or usability test findings regarding common industry patterns.
3. **Synthesize Findings**: Document why a chosen interaction model is superior for the user's specific context.
